# Phase 5D — 助詞重複の高確度な限定検出

## なぜ全助詞の連続を正規表現で検出しないか

同じ仮名が連続していても、語の境界をまたいでいるとは限らない。
例えば次の文は自然であり、文字だけで判定すると誤検知を生む。

- 母ははっきり答えました
- 人ががんばっています
- 川ににじが映りました

現時点の日本語Writing Toolkitは形態素解析を行わず、品詞・
係り受け・構文解析の裏付けがない。したがって `はは`,
`がが`, `にに` を無差別に警告する案は採用しない。

## v1の範囲

新規の `wording/doubled-object-particle` は目的語格の
`を` の連続入力ミスが疑われる次の**限定的な表層表現**だけを対象にする。

- `をを`
- `を を` / `を　を`
- `を、を` / `を， を` / `を, を`

二文字目（不要である可能性が高い助詞）だけをハイライトする。
三連続の `ををを` では2文字目と3文字目の両方を検出する。
ただし、不要な文字の削除が文法上安全だと断言できないため
`fixKind: none`、自動置換もQuick Fixも行わない。

## 偽陽性対策

- 文中の合法的な複数 `を`、その他の助詞や助詞から始まる単語は対象外
- 「」/『』の例示・会話、Markdown blockquoteは除外
- コード、URL、HTMLコメント等は既存のmaskDocumentに従う
- 改行を跨がない（別段落をまたいでマッチさせない）
- UTF-16位置情報とEmojiを考慮する

一般・Technicalでは`info`、Strictでは`warning`、
Minimalは未適用。ルールは個別に有効/無効を設定可能。

## 検証

- Positive 6表現、三連続の境界、Unicode位置
- Negative：自然な助詞の繰返し、「はは」等の語彙
- Markdown/URL/Quote/Code遮蔽
- Existing textlint/RuleProviderとのレジストリ整合
- `japanese-quality-v2.json` のGold Labelと厳密一致
- 全TypeScript/Vitest、Bunスモーク、Vite/Pages・asset path

## 次の検討

助詞のより広い誤用は、形態素解析を使った専門ルールの
精度評価PRを挟み、実文書に対するFP率を測定してから対象を増やす。
単に「同一助詞が連続したら誤り」という一般化はしない。
