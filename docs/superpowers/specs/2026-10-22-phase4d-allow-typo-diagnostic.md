# Phase 4D — 診断パネルから誤字辞書の例外登録

## 目的

`wording/common-typo` は高確度の表記候補だけを検出するが、
製品名、ブランド名、社内用語、固有名詞では敢えて「デバック」などの
表記を使用する場合がある。過度な誤検知を抑制できるよう、
ユーザーが診断から該当表記を**正式表記として明示的に許可**できる
ワークフローを追加する。

## 画面・操作仕様

- 誤字ルールの Suggestion 診断に「この表記を許可」ボタンを表示。
- 利用者が押した時だけ、対象表記を既存 `terminology` へ
  `{ preferred: <表記>, rejected: [], caseSensitive: true }` として登録。
- 診断をクリックしてジャンプする操作と、修正候補を適用する操作は維持。
- 登録成功後は再解析し、同一の疑わしい表記に対する内蔵辞書の
  警告を取り除く。本文自体は変更しない。
- 設定 > 用語統一に「誤字辞書の例外（正式表記）」として表示。
  削除すれば元の診断が復活する。
- 設定画面は却下表記を任意入力に変更。通常の Preferred/Rejected
  表記統一ルールは従来どおり使える。
- 例外は使用中の設定/RuleProfile経路に保存する。別のプロファイルや
  ワークスペースでの共有は保証しない。

## 安全性

実行時の診断表示だけを信用しない。操作時に原文から対象範囲を再取得して
以下を検証する。

1. rule ID `wording/common-typo` かつ `fixKind = suggestion`。
2. offset は整数、UTF-16の正しい範囲、0以上、本文の長さ以下。
3. spanの原文が内蔵辞書に存在し、その訂正候補も一致。
4. 既存の `preferred` / `rejected` に同表記があれば二重登録しない。
5. IDの空文字・重複を認めない。用語数の既存上限500件を超えない。
6. ルール設定変更後の古い非同期Worker結果はrevision更新で無効化。

登録失敗時に本文や用語集を変更しない。ルールや文書単位の
推測的な「AI学習」ではないことを明示する。

## 互換性と制約

- schema v1の `TermEntry.rejected: []` を再利用する。Migration不要。
- IndexedDB以外の新規保存先・API・通信・LLM・依存ライブラリは不要。
- 文書本文のプライバシーモードを変更しない。
- これは内蔵の**誤字辞書のみ**の例外で、NGワードや表記統一の診断全体を
  非表示にするものではない。
- Word単位の明示的な許可であり、選択した1箇所だけの非表示ではない。

## 検証

- 正式表記の登録・設定インポート・削除後の復元
- 誤ったRule ID、stale text、偽装された置換候補
- 不正offset、重複ID、ユーザー用語の衝突、用語数上限
- 絵文字を含むUTF-16 offset、複数出現、他の誤字の独立性
- RuleProviderと既存設定スキーマの互換
- TypeScript、全Vitest、本番ビルド、Pagesビルド、asset paths

### 将来の拡張

「この文書だけ無視」など文書固有の非永続的診断抑制は別フェーズ。
テスト用の実文書/コーパスについては権利・個人情報を確認し、
代表性のない合成例文に対して精度100%と主張しない。
