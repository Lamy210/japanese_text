# Phase 4C — 内蔵誤字辞書の拡張とユーザー用語集の優先

## 目的と採用理由

日本語校正では、一般的な誤表記が製品名・ブランド名・社内用語では
意図された表記である場合がある。辞書の件数を増やすだけでは誤検知が増える。
そこで既存のユーザー編集可能な `terminology` を内蔵誤字辞書より優先し、
ルールの判断が衝突しないようにする。

## 辞書

初期の4組に以下の4組を追加する（合計8組）。

| 検出表記 | 手動修正候補 |
| --- | --- |
| コミニュティ | コミュニティ |
| アクセサビリティ | アクセシビリティ |
| シュミレーター | シミュレーター |
| シュミレータ | シミュレータ |

「シミュレータ」「シミュレーター」のような長音のスタイル差は
訂正対象ではない。これらは形態素解析や意味判断によらない
明示的な辞書パターンであり、一般的な誤字・脱字の網羅は主張しない。

## 優先順位

同一の疑わしい表記がユーザー用語集の `preferred` または
いずれかの `rejected` に**完全一致**する場合、内蔵誤字辞書は
その表記の診断を出さない。

- preferred に一致: ユーザーがその表記を標準と認めている
- rejected に一致: 用語統一ルールが個別の適切な候補を管理する
- その他の内蔵辞書エントリは通常どおり検査する
- 部分一致だけでは抑制しない
- ユーザー用語集の更新は既存のRuleProvider経由で実行時に反映する

新しい保存項目・設定画面・移行・API・外部通信は不要。用語集の
ユーザー定義は既存のワークスペース設定を通じて扱われる。
校正ルール単体の有効化や重要度変更は従来どおりRuleProfileで設定できる。

## 適用ポリシーと偽陽性対策

- すべて `fixKind: suggestion` とする。自動Formatでは適用しない
- カタカナ語に隣接する別のカタカナ・英数字は製品名等の可能性として除外
- 「」・『』、Markdownコード・URL・HTMLコメント、引用ブロックを除外
- Markdown見出し・箇条書きの本文は検出対象
- 診断位置はUTF-16 offsetで厳密に保存
- 空文字・意味依存の自動言い換え・大型辞書の無断取り込みを避ける

## 評価方法

`tests/corpus/common-typo-v1.json` は人工的に作成した正例と負例である。
`tests/corpus/common-typo-corpus.test.ts` は位置を厳密に比較し、
TP / FP / FN を計測する。**これを実文書に対する精度指標と解釈しない。**

追加検証はユーザー用語優先・Unicode・引用・リンク・コードブロック・
製品名接尾語を含む。最終PRコミットの型チェック、全Vitest、
本番ビルド、GitHub Pagesビルド、Workerパス検証をマージ条件とする。
